# 本地数据与冲突处理

题库使用 `problems/<题号>`，比赛使用 `contests/<比赛 ID>/<全局题号>`。标题不参与路径。代码来源关联、官方样例基线与修订号保存在 `.better-accoding/bindings/<bindingId>.json`。

每个题目目录包含 `problem.json`、`problem.md` 或净化后的 `statement.html`，以及 `tests/tests.json`。每个用例以稳定 ID 命名 `.in` / `.out`；官方样例原版位于 `tests/originals`。`tests.json` 和 `problem.json` 是生成的元数据视图，请通过扩展修改名称、顺序和关联。输入和预期文件可以直接编辑，空 `.out` 表示期望空输出；关闭校验的用例不使用输出文件。

卡片输入框标题旁的文件按钮打开真正的用例文件。评测、调试和切题前会保存卡片草稿；评测与调试还会保存已经打开的用例文件。保存失败会停止操作。外部文件修改被读取后递增修订号，迟到的卡片保存不会覆盖它；冲突条允许使用已保存版本、明确用草稿覆盖，或复制草稿。

扩展使用工作区写入锁协调多个窗口。写入事务先记录待写内容，再写用例文件，最后提交元数据修订号并发送保存确认。进程中断后会检查文件是否仍是事务记录的旧版或新版，再继续恢复；存在第三种外部内容时停止恢复，保留文件与 `.better-accoding/transactions` 记录。不要删除未处理的事务记录。

旧开发候选只存嵌入式 JSON。首次加载会先将原文件备份到 `.better-accoding/backups`，再生成独立用例文件。未知 schema、缺失用例文件、符号链接或冲突不会被自动覆盖。元数据仍保留正文快照用于恢复。删除用例保留撤销记录及原文件，普通同步不会复活已删除的官方样例。

请备份整个题目目录与 `.better-accoding`，而不仅是源码。以上工作区数据不包含登录凭据、账号身份或个人提交历史。

题面图片保存在 `.better-accoding/images`，以内容哈希命名；题目元数据将原图片 URL 的哈希映射到本地文件。导入和同步时更新，断网时可复用校验通过的缓存。支持 PNG/JPEG/GIF/WebP 与净化后的 SVG，每张最多 8 MiB、每题最多 40 张；失败会显示提示，打开题目不会自动请求网络。备份题目时请包含这些图片。SVG 外部引用、脚本和不支持的富文本内容不会保留。

工作区总索引 `.better-accoding/workspace.json` 由绑定事务数据派生，缺失或陈旧时自动重建；未知版本或损坏数据会保留并报错。比赛 `contest.json` 保存名称、时间、全部题目及题序。首次只勾选部分题目时，整场同步不会补入当时未选的旧题，只加入后来新增的题目。当前题目同步不会消耗整场同步的新增题目基线。

比赛移除题目后，源码和用例原样保留，题单显示“已移除”，可继续离线练习但不能交题；重新同步确认题目恢复后解除限制。同步网络或权限失败不会当作全部题目被移除。旧工作区没有完整名册时，以已有本地题目为基线，首次整场同步会导入其他当前可见题目。
